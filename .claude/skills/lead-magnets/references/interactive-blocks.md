# Каталог интерактивных блоков

Стандартный набор механик, из которых собирается лид-магнит — берёт скорость и консистентность (не изобретать заново каждый раз), но не ограничивает: если сценарий просит механику, которой нет в каталоге, придумывай новую по тому же принципу (чистый HTML/CSS/минимум vanilla JS, без внешних библиотек — страница должна быть самодостаточной и лёгкой).

Все блоки — на чистом HTML/CSS/vanilla JS, без фреймворков и внешних CDN-зависимостей (страница должна открываться и работать без интернета, кроме счётчика метрики и формы). Разметка блоков — в `templates/page-template.html`, там же рабочие примеры каждого блока ниже.

## 1. Прогресс-бар дочитывания
Тонкая полоса вверху страницы, заполняется по мере скролла. Не столько интерактив, сколько психологический крючок "я почти дочитал". Ставь почти всегда — дешёво и увеличивает дочитываемость.

## 2. Квиз с результатом (ветвление)
Несколько вопросов → на основе ответов показывается один из 2-4 заготовленных результатов ("ты — тип X, тебе подходит..."). Хорошо работает как открывающий или закрывающий блок — вовлекает в начале или персонализирует CTA в конце.

## 3. Опрос "а как у тебя"
Один вопрос с вариантами ответа, после клика — сразу показывается агрегированная реакция ("62% ответили так же") — можно захардкодить правдоподобные цифры при первой публикации, до накопления реальных данных, но пометь это в `structure.md`, чтобы потом заменить на настоящие.

## 4. Калькулятор
Пользователь вводит 1-3 параметра (числа/выбор) → блок считает и показывает результат (сколько теряет/экономит/зарабатывает). Сильный блок для B2B и тем про деньги/время.

## 5. Раскрывающиеся карточки (аккордеон/флип)
Заголовок-вопрос или тизер → клик открывает содержимое. Хорошо для "мифы vs реальность", FAQ внутри лонгрида, чек-листов, которые не нужно видеть все сразу.

## 6. Слайдер "до / после"
Два состояния, перетаскиваемая граница между ними (или переключатель, если тач-жесты избыточны). Для тем про трансформацию, результат, "было — стало".

## 7. Чек-лист с сохранением состояния
Список пунктов с чекбоксами, прогресс "отмечено X из Y" наверху блока. Состояние можно хранить в localStorage, чтобы не сбрасывалось при повторном заходе — не обязательно, но приятная деталь.

## 8. Финальный CTA-блок
Не совсем "интерактив", но обязательный элемент: форма или кнопка, которая явно завершает прогрев. Формулировка CTA должна прямо продолжать логику последнего смыслового блока, а не быть generic "оставьте заявку".

## Правила выбора блоков

- Не пихай все 8 в один лид-магнит — это утомляет. Обычно 3-5 механик на один лонгрид, привязанных к конкретным смысловым точкам из `structure.md`.
- Каждый интерактивный блок должен либо продвигать прогрев (раскрывать боль/выгоду), либо квалифицировать читателя (собирать данные о нём для персонализации CTA) — не ставь ради развлечения без смысловой нагрузки.
- Мобильный экран — приоритет: слайдеры и перетаскивания должны работать тач-жестами, кнопки — не мельче 44px по высоте.
