# AI Assistant Agent

Скилл собирает «операционную систему» для задач: всё, о чём договорились в чатах, личке, почте,
созвонах и CRM, попадает в одно место. Дальше ассистент сам следит за сроками, пинает исполнителей
и отвечает на вопросы по работе, потому что у него весь контекст.

Наглядная схема и демо всех модулей есть в репозитории: страница `ai-assistant/index.html`
(на воркере — `/ai-assistant`). Показывай её клиенту, когда нужно объяснить, что получится.
Похожая боевая связка с личкой уже работает в `crm/` (`/crm`), дашборд маркетинга лежит в `dashboard/`.
Стек тот же: один Cloudflare Worker, KV, Claude API, Telegram Bot API.

## Когда использовать

- «Хочу ассистента, который собирает задачи из чатов и следит за сроками»
- «Бот в рабочем чате, чтобы ставил задачи и напоминал»
- «Подключить личку через Telegram Business, чтобы не терять обещания клиентам»
- «Таск-трекер с ИИ», «утренний брифинг», «ежедневный отчёт по сотрудникам»
- «База знаний / скилл о себе, проекте и команде, которую ИИ сам обновляет»
- «Связать задачи с дашбордом маркетинга и CRM»
- «Готовлю воркшоп про ИИ-ассистента»

## Первое правило: сначала вопросы, потом код

Ни токенов, ни кода, пока нет ответов. Задай коротким списком и запиши ответы в `assistant/BRIEF.md` проекта:

1. **Команда.** Кто в ней, роли, Telegram-username каждого. Кто руководитель (получает эскалации)?
2. **Источники.** Что подключаем: рабочие чаты (какие), личку через Business-бота (есть ли Telegram Premium),
   почту (Gmail или Яндекс), календарь, CRM (amoCRM, Bitrix24, другая), Zoom, дашборд маркетинга?
3. **Проекты.** Как называются направления работы (Реклама, Контент, Продажи…), чтобы ассистент раскладывал задачи.
4. **Сроки по умолчанию.** Если срок не назван: спросить у исполнителя или ставить «через сутки, 18:00»?
5. **Напоминания.** Тон (мягко / по делу / жёстко), тихие часы, через сколько эскалировать руководителю,
   можно ли пинговать в общий чат.
6. **Интерфейсы.** Нужен ли веб-трекер, утренний брифинг, ежедневный отчёт, вопросы к ИИ? Куда слать отчёты?
7. **Часовой пояс** и рабочие часы команды.
8. **Модель.** Для разбора каждого сообщения по умолчанию `claude-haiku-5-5` (быстро и дёшево),
   для отчётов и вопросов `claude-sonnet-5-5`. Спроси, устраивает ли.
9. **Где живёт.** Свой Cloudflare-аккаунт клиента или общий воркер.

## Маршрутизация по подкоманде

| Подкоманда | Что делает |
|---|---|
| `brief` | Задаёт вопросы выше, пишет `assistant/BRIEF.md` |
| `access` | По одному источнику: где взять доступ, куда положить, как проверить (раздел «Доступы») |
| `build` | Разворачивает воркер, KV, вебхук, модель данных (разделы «Архитектура», «Модель данных») |
| `parse` | Настраивает разбор сообщений в задачи (раздел «Разбор сообщений») |
| `remind` | Лестница напоминаний, тихие часы, эскалации (раздел «Напоминания») |
| `memory` | База знаний: три файла, правила обновления (раздел «Память») |
| `report` | Утренний брифинг, ежедневный отчёт по людям и проектам, итоги недели |
| `ask` | Вопросы к ИИ в боте (`/ask`) и на странице трекера |
| `triggers` | Задачи из метрик дашборда и событий CRM |

| `workshop` | Сценарий воркшопа по сборке (раздел «Воркшоп») |

Без подкоманды начинай с `brief`, дальше по фазам.

## Фазы сборки

| # | Фаза | Результат | Показать клиенту? |
|---|---|---|---|
| 0 | Бриф | `assistant/BRIEF.md` с ответами | Да, без этого не начинаем |
| 1 | MVP | Бот в одном рабочем чате + задачи в KV + напоминания по cron | Да: неделю живут с ботом |
| 2 | Источники | Business-бот, почта, календарь, CRM, Zoom — по одному, каждый проверен | Да, после каждого |
| 3 | Память | Три файла базы знаний, ассистент сам их дополняет | Да: сверить факты |
| 4 | Интерфейсы | Веб-трекер, брифинг, отчёты, вопросы к ИИ | Да |
| 5 | Триггеры и фишки | Задачи из дашборда и CRM, детектор обещаний, стендап и т. д. | По желанию |

Не подключай всё разом. Один источник → проверка на живых сообщениях → следующий.

## Архитектура

```
Telegram (группы, личка, Business) ─┐
Почта / Календарь (Google API) ─────┤
CRM (вебхуки + API) ─────────────────┼─▶ Cloudflare Worker ─▶ Claude API (разбор, ответы)
Zoom (recording.completed) ──────────┤        │
Дашборд маркетинга (data.json) ──────┘        ├─▶ KV: задачи, история, база знаний, настройки
                                              ├─▶ Cron */15: сроки, напоминания, брифинг, отчёты
                                              └─▶ Telegram: карточки задач, напоминания; веб-трекер /tasks
```

Маршруты воркера (минимум): `POST /tg` — вебхук Telegram, `POST /crm-hook`, `POST /zoom-hook`,
`GET /oauth/google` — вход Google, `GET /tasks` — трекер, `POST /api/tasks/*` — правки задач,
`POST /api/ask` — вопрос к ИИ. Плюс `scheduled()` для cron.

## Модель данных

Задача в KV (ключ `task:<id>`, индекс `tasks:open`):

```json
{
  "id": "t_8f2a",
  "title": "Запустить ретаргет на брошенные корзины",
  "assignee": "masha",
  "due": "2026-10-15T18:00:00+03:00",
  "priority": "normal",
  "project": "Реклама",
  "status": "todo",
  "source": { "type": "tg_group", "chat": "Маркетинг", "message_id": 4812, "link": "https://t.me/c/…/4812" },
  "createdBy": "me",
  "createdAt": "2026-10-13T11:42:00+03:00",
  "accepted": true,
  "history": [
    { "at": "2026-10-14T18:00:00+03:00", "kind": "remind_d24", "to": "masha" }
  ]
}
```

- `status`: `todo` → `doing` → `done` (или `cancelled`). Закрытие фиксирует `doneAt`, чтобы считать «в срок».
- `source.type`: `tg_group`, `tg_business`, `mail`, `calendar`, `crm`, `zoom`, `dashboard`, `web`.
- Люди — в `team.json` (KV `team`): id, имя, роль, Telegram `chat_id` (появляется после `/start`), руководитель.
- История напоминаний пишется в задачу: так cron не шлёт одно и то же дважды.

## Разбор сообщений

Каждое новое сообщение (текст или расшифровка голосового) идёт в Claude вместе с контекстом:
команда, проекты, текущая дата и часовой пояс, выжимка из базы знаний, 5–10 предыдущих сообщений чата
(чтобы понимать ответы на сообщения).

Ответ строго в JSON:

```json
{
  "is_task": true,
  "confidence": 0.86,
  "title": "Поправить баннер на лендинге",
  "assignee": "dima",
  "assignee_reason": "обращение по имени",
  "due": "2026-10-15T15:00:00+03:00",
  "due_text": "к 15:00",
  "priority": "high",
  "project": "Креативы",
  "is_promise": false,
  "facts": [ { "file": "team", "key": "dima", "text": "в отпуске 20–27 октября" } ]
}
```

Правила:
- Короткие «ок», «спасибо», «понял», реакции отсекай **до** запроса к модели — экономия денег.
- `confidence < 0.6` или нет исполнителя → бот спрашивает кнопками: «Это задача? Кому? Какой срок?»
- Обещание автора («скину завтра», «пришлю КП») — задача самому автору, `is_promise: true`.
- Просьба клиента в личке («пришлите до пятницы») — задача владельцу лички.
- Срок без времени → 18:00 (или как в брифе). «До обеда» → 13:00, «утром» → 11:00, «до конца недели» → пятница 18:00.
- Название задачи — с глагола в инфинитиве: «Отправить КП», а не «Скину вам КП».
- После разбора бот присылает карточку с кнопками «Принять» / «Другой срок» / «Не задача».
  Задача стартует только после «Принять» исполнителем.

## Напоминания

Cron каждые 15 минут проходит открытые задачи. Лестница по умолчанию:

| Когда | Кому | Канал |
|---|---|---|
| Сразу после создания | исполнителю | личка от бота |
| За 24 часа | исполнителю | личка |
| За 2 часа | исполнителю | личка |
| +1 час после срока | исполнителю | личка |
| +4 часа после срока | руководителю | личка руководителя |
| +24 часа (только тон «жёстко» и если разрешено) | общий чат | группа |

- **Тихие часы** (по умолчанию 21:00–9:00 по часовому поясу команды): всё, что выпадает на них, переносится на 9:00.
- **Тон** берётся из настроек: мягко / по делу / жёстко. Текст напоминания всегда содержит название задачи и срок датой и временем.
- **Лимит:** не больше трёх напоминаний исполнителю по одной задаче, дальше только эскалация.
- **Учёт памяти:** если в базе знаний сказано «Диме хватает одного напоминания» или человек в отпуске — ассистент меняет поведение.
- Кнопки в напоминании: «Готово», «Перенести», «Нужна помощь» (callback_query → правка задачи).

## Память

Три markdown-файла в KV — по сути скилл Claude о контексте:

- `kb:about-me` — роль руководителя, рабочие часы, формат отчётов, как пишет, приоритеты квартала.
- `kb:project` — продукт, бюджеты, ключевые метрики, подрядчики, клиенты в работе и договорённости с ними.
- `kb:team` — по каждому: роль, зоны, сроки соблюдает на N%, особенности, текущий статус (отпуск и т. п.).

Факты из разбора (`facts`) ассистент дописывает сам и сообщает: «Запомнил: Маша в отпуске 20–27». Ошибку отменяют кнопкой.
Выжимка из базы уходит в каждый запрос к Claude. Раз в месяц предложи владельцу пролистать и удалить устаревшее.

## Отчёты и брифинг

- **Утренний брифинг** (9:00, руководителю): сроки сегодня, просрочки с именами, что ждут лично от него, встречи дня, один совет.
- **Ежедневный отчёт** (19:00): что закрыто, что сорвано, что в работе — отдельно по каждому сотруднику и по каждому проекту.
  Куда: личка, рабочий чат или почта — как в брифе. Формат берётся из `kb:about-me`.
- **Итоги недели** (понедельник утром): цифры за неделю, кто что закрыл, риски.
- Начинай отчёт с проблем, а не с успехов. Каждая цифра — из данных задач, не выдумывай.

## Вопросы к ИИ

Команда `/ask` в боте и окно «Спросить ИИ» на странице трекера. Перед вопросом воркер собирает выжимку:
открытые задачи, события за неделю, база знаний, цифры дашборда. Ответ ссылается на конкретные задачи.
Частые вопросы вынеси кнопками: «Что горит сегодня и завтра?», «Кто перегружен?», «Что я обещал и не сделал?»,
«Отчёт собственнику», «Почему просрочки?», «Что по клиенту X?».

## Триггеры из дашборда и CRM

Правило = метрика + окно + порог + ответственный + срок. Примеры:
- CPL в Директе вырос больше чем на 30% за 3 дня → таргетологу «проверить кампании», срок сегодня 18:00.
- Лид без ответа больше 2 часов → менеджеру; ещё 4 часа без ответа → руководителю.
- Сделка без движения 7 дней → менеджеру «следующий шаг».
- Конверсия лендинга ниже порога → дизайнеру/руководителю.
Пороги по скользящему среднему, иначе ложные тревоги на выходных. Задачу по метрике закрывают, когда цифра вернулась в норму.

## Доступы

Для каждого источника: скажи, где взять, куда положить, как проверить. Все ключи — только через `wrangler secret put`.

**Токен бота (BOT_TOKEN).** @BotFather → `/newbot` → имя и username на `bot` → токен.
`/setprivacy` → бот → **Disable**, иначе в группах бот видит только команды. Если privacy меняли после
добавления в группу — удалить бота и добавить заново. Вебхук:
`https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<воркер>/tg&secret_token=<секрет>&allowed_updates=["message","callback_query","business_connection","business_message"]`.
Проверяй заголовок `X-Telegram-Bot-Api-Secret-Token`. Каждый сотрудник один раз пишет боту `/start`.

**Telegram Business.** Нужен Telegram Premium на аккаунте владельца лички. @BotFather → бот → Bot Settings →
Business Mode → включить. Telegram: Настройки → Telegram для бизнеса → Чат-боты → username бота →
доступ «все, кроме…» или «только выбранные» (личные исключить). Право отвечать от имени владельца — только если нужно.
Бот получает `business_message`; отвечать от имени владельца — `sendMessage` с `business_connection_id`.

**Голосовые.** Бот берёт `voice` → `getFile` → расшифровка: проще всего Workers AI (Whisper) через
`[ai] binding = "AI"` в `wrangler.toml`, без отдельного ключа; либо Yandex SpeechKit (`STT_KEY`).

**Почта Gmail.** Google Cloud Console → проект → Library → Gmail API → Enable. OAuth consent screen
(тестовый пользователь — владелец). Credentials → OAuth client ID → Web application, redirect
`https://<воркер>/oauth/google`. `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` в секреты. Владелец один раз
проходит вход, refresh token сохраняется в KV. Cron раз в 10–15 минут читает новые письма; рассылки и уведомления
отсеиваются по категориям и отправителям. Яндекс.Почта: правило пересылки на адрес Cloudflare Email Routing → воркер.

**Календарь.** В том же проекте Google Calendar API → Enable, доступ `calendar.readonly`
(или к событиям, если ассистент ставит встречи), повторный вход. За 15 минут до встречи — справка по контрагенту.

**CRM.** amoCRM: Настройки → Интеграции → создать внешнюю интеграцию → долгосрочный токен; Web hooks на
`/crm-hook` (сделка добавлена, смена этапа, примечание). Bitrix24: Приложения → Разработчикам → Другое →
входящий вебхук с правами CRM, исходящий на события. Токен — `CRM_TOKEN`.

**Zoom.** Платный тариф с облачной записью, права админа. marketplace.zoom.us → Develop → Build App →
Server-to-Server OAuth. Account ID, Client ID, Client Secret — в секреты. Scopes на чтение записей.
Event Subscriptions → `/zoom-hook`, событие «All Recordings have completed»; воркер отвечает на
`endpoint.url_validation`. Включить облачную запись и Audio transcript. Итоги созвона — на подтверждение человеку, потом задачи.

**Claude API.** console.anthropic.com → Billing (пополнить, поставить лимит) → API Keys → Create Key → `CLAUDE_API`.

**Cloudflare.** dash.cloudflare.com (бесплатного плана хватает для старта, cron в нём есть) →
`npm i -g wrangler` → `wrangler login` → `wrangler kv namespace create TASKS` → id в `wrangler.toml` →
`[triggers] crons = ["*/15 * * * *"]` → `wrangler deploy`.

**Дашборд маркетинга.** Если на том же воркере — читать `/dashboard/data.json`; если на другом — service binding.

## Правила, которые не обсуждаются

1. **Прозрачность.** Команда знает, что бот в чате записывает задачи. Первое сообщение бота в группе — об этом.
2. **Подтверждение.** Задача стартует после «Принять». Спорный срок исполнитель переносит кнопкой.
3. **Клиентам — только через человека.** Ассистент готовит черновик ответа, отправляет владелец.
4. **Личные чаты не трогаем.** В Business-боте — режим «все, кроме…» с исключением личных.
5. **Ключи — в секретах.** Ни одного токена в коде и в репозитории.
6. **Цифры из данных.** Отчёты и ответы опираются на задачи и метрики. Нет данных — так и говорим.
7. **Тишина ночью.** Тихие часы и лимит напоминаний включены по умолчанию.
8. **Источники по одному.** Каждый новый источник проверяем на живых сообщениях, прежде чем подключать следующий.

## Проверка

- Сообщение «Маша, запусти ретаргет до четверга» → карточка задачи: Маша, ближайший четверг 18:00, проект «Реклама».
- «Окей, спасибо!» → задача не создаётся, модель не вызывается.
- «Скину КП завтра до обеда» от владельца → задача ему же, завтра 13:00, отмечена как обещание.
- Голосовое с тремя поручениями → три задачи трём людям.
- Сдвиг времени (тестовый режим cron с подменой «сейчас»): напоминания за сутки, за 2 часа, после срока,
  эскалация через 4 часа; ночью ничего не уходит, всё переносится на 9:00.
- Повторный прогон cron не шлёт те же напоминания второй раз.
- «Принять» / «Перенести» / «Готово» меняют задачу, и это видно в трекере.
- Брифинг и ежедневный отчёт собираются по реальным задачам, по людям и проектам.
- Факт «Маша в отпуске 20–27» попадает в `kb:team`, напоминания Маше в эти дни не уходят.
- Падение одного источника (почта, CRM) не ломает остальные: ошибка видна в трекере.

## Воркшоп

Опора — страница `/ai-assistant`: схема, разбор сообщения, сцены в Telegram, доска с машиной времени,
лестница напоминаний, память, вопросы к ИИ, триггеры, конструктор с промптом. Сценарий на 90 минут:

| Время | Блок | Что делаем |
|---|---|---|
| 0–10 | Боль | Где теряются задачи: чаты, личка, созвоны. Опрос участников |
| 10–25 | Схема | Источники → OS → результаты. Показ сцен в Telegram |
| 25–45 | Живая сборка | BotFather, вебхук, бот в тестовой группе, первая задача из сообщения |
| 45–60 | Напоминания и память | Машина времени на доске, лестница, факты в базе знаний |
| 60–75 | Конструктор | Каждый собирает свою систему, копирует промпт для Claude Code |
| 75–90 | Вопросы | Business-бот, почта, CRM, Zoom: что подключать первым |

Техчек: у участников Telegram и аккаунт Cloudflare; у ведущего — тестовая группа, заранее созданный бот,
ключ Claude API в секретах, открытая страница `/ai-assistant`. Домашнее задание: неделю пожить с ботом
в одном рабочем чате и принести список задач, которые он поймал и пропустил.
