# Marketing Dashboard Agent

Скилл делает две вещи:

1. **Собирает дашборд** отдела маркетинга под конкретную компанию: сырые выгрузки из пяти источников →
   единая модель данных → светлый интерактивный дашборд → ИИ-инсайты → автообновление и уведомления.
2. **Готовит воркшоп** по этой сборке: сценарий с таймингом, техчек-лист, демо-данные на случай,
   когда у участника нет доступов, раздатку и домашнее задание.

Рабочий образец лежит в репозитории: `dashboard/` — открывается двойным кликом по `index.html`,
собирается одной командой `node dashboard/collectors/collect.js`. **Не пиши дашборд с нуля** —
копируй `dashboard/` в проект клиента и меняй под его данные.

## Когда использовать

- «Собери дашборд по маркетингу», «сквозная аналитика», «свести Директ и amoCRM»
- «Нужны ИИ-инсайты по рекламе», «пусть сам находит, где сливается бюджет»
- «Настрой автообновление и уведомления руководителю»
- «Готовлю воркшоп про дашборд» — сценарий, техничка, раздатка

## Маршрутизация по подкоманде

| Подкоманда | Что делает | Куда смотреть |
|---|---|---|
| `brief` | Собирает бриф: какие источники, какие метрики, кто читатель дашборда | `references/brief.md` |
| `access` | Ведёт по доступам и токенам, проверяет каждый источник по очереди | `references/connectors.md` |
| `build` | Разворачивает дашборд под клиента, правит модель данных и блоки | `references/data-model.md` |
| `insights` | Настраивает правила и промпт для ИИ-инсайтов | `references/insights.md` |
| `automate` | Автообновление (Actions / cron) и дайджест в Telegram | `references/automation.md` |
| `workshop` | Сценарий воркшопа, тайминг, техчек-лист, раздатка | `references/workshop.md` |
| `troubleshoot` | Разбор ошибок API и кривых данных | `references/troubleshooting.md` |

Без подкоманды — начинай с `brief`, дальше по порядку.

Готовые материалы: `assets/brief-template.md` — шаблон брифа, `assets/handout.md` — раздатка участнику
воркшопа с командами и чек-листом доступов.

## Главное правило: сначала модель, потом картинки

Порядок работы, от которого не отступаем:

```
бриф → доступы → сырые выгрузки → единая модель (data/dashboard.json) → дашборд → инсайты → автообновление
```

Дашборд не ходит в API. Он читает один готовый JSON. Это даёт три вещи:
страница открывается офлайн и мгновенно, источники можно менять не трогая вёрстку,
а любой блок дашборда всегда можно объяснить: вот поле в модели, вот коннектор, который его заполнил.

## Пять фаз сборки

| # | Фаза | Результат | Чекпоинт с клиентом? |
|---|---|---|---|
| 0 | Бриф | Список источников, метрик и вопросов, на которые дашборд отвечает | Да — без этого не начинаем |
| 1 | Доступы | Работающие токены, каждый источник проверен отдельно | Нет |
| 2 | Модель | `dashboard/data/dashboard.json` с реальными данными | Да — сверяем итоги с тем, что клиент видит в кабинетах |
| 3 | Дашборд | Страница под данные клиента | Да — показываем и правим формулировки |
| 4 | Инсайты + автоматизация | Правила, промпт, расписание, уведомления | Да — согласуем, кому и когда приходит дайджест |

## Правила, которые не обсуждаются

1. **Токены — только в переменных окружения.** В конфиге лежит `"env:AMO_TOKEN"`, в репозитории —
   никогда сам токен. `collectors/config.json` в `.gitignore`.
2. **Цифры считают правила, а не модель.** Claude формулирует выводы по посчитанным числам.
   Инсайт без цифры из данных — выдумка, такой не показываем.
3. **Один источник упал — дашборд живёт.** Ошибка помечается статусом, остальные блоки считаются.
   Молча показывать нули нельзя: в шапке видно, что источник отвалился.
4. **Сверяем итоги с кабинетами до того, как рисовать.** Расход за период должен сойтись с Директом,
   число сделок — с amoCRM. Расхождение больше 2% — это баг в модели, а не «особенность выгрузки».
5. **Заявка и лид — не одно и то же.** До сборки договариваемся, что считаем заявкой, что квалифицированной,
   в какой момент сделка «выиграна». Эти определения пишем в бриф и повторяем в подписи к блоку.
6. **Дайджест руководителю — только когда есть что сказать.** Ежедневное «всё хорошо» перестают читать
   за неделю; шлём при критичном инсайте.

## Быстрая проверка результата

- Дашборд открывается двойным кликом, без сервера и без интернета.
- `node collect.js` отрабатывает без ошибок и пишет свежий `data/dashboard.json`.
- Каждая цифра на странице прослеживается до источника — блок «Откуда берутся данные» заполнен.
- Каждый инсайт заканчивается конкретным действием и оценкой эффекта.
- На экране 390px ничего не уезжает за край: таблицы скроллятся внутри себя.
