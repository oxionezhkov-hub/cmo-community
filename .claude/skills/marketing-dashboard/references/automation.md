# Фаза 4. Автообновление и уведомления

## Расписание

Два рабочих варианта, оба лежат в `dashboard/automation/`:

1. **GitHub Actions** (`github-actions.yml`) — раз в сутки собирает данные, коммитит свежий
   `data/dashboard.json` и публикует статику. Токены — в секретах репозитория, имена те же, что в `config.json`.
2. **Cron на Cloudflare Worker** (`cron-worker.md`) — если дашборд уже живёт на воркере.
   Коллекторы написаны на голом `fetch`, поэтому переносятся почти без правок.

Частота: раз в сутки достаточно для отчётности. Раз в час имеет смысл, только если на дашборд
смотрят в течение дня и источники обновляются так же часто (Директ отдаёт статистику с задержкой,
amoCRM — сразу; общая свежесть равна самому медленному источнику).

## Уведомления руководителю

```bash
node collect.js --mode=live --ai --notify
```

Правила, которые делают дайджест читаемым:

- **Только при критичном инсайте** (`notify.onlyIfCritical: true`). Ежедневное «всё хорошо»
  перестают открывать за неделю.
- **Три пункта максимум.** Дайджест — это не дашборд в текстовом виде, а повод открыть дашборд.
- **Каждый пункт с действием.** «CPL вырос» — плохой пункт, «CPL вырос из-за кампании X, предлагаю урезать бюджет вдвое» — хороший.
- **Ссылка на дашборд в конце.** Человек должен иметь возможность провалиться в цифры.
- Отдельный бот для уведомлений, отдельный чат. Не шлите в общий чат отдела: там дайджест утонет.

## Что делать при падении источника

Сборка не падает целиком: источник помечается статусом `error`, остальные блоки считаются,
в шапке дашборда и в разделе «Откуда берутся данные» видно, что сломалось.
Это сознательное решение: дашборд с четырьмя источниками из пяти полезнее, чем страница с ошибкой.

Чего нельзя делать: показывать нули вместо данных молча. Если так, руководитель примет решение
по пустому графику — а это хуже, чем отсутствие дашборда.

При регулярных падениях добавьте в дайджест строку «источник X недоступен N дней» — техдолг должен быть виден бизнесу.

## Хранение истории

`data/dashboard.json` перезаписывается. Если нужна история — коммитьте файл (Actions так и делает):
git становится бесплатной машиной времени, можно сравнить любую пару дат.
Для серьёзной аналитики по истории — складывайте `daily` в отдельную таблицу или БД, а не растите JSON.
